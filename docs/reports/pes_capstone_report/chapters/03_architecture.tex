\chapter{Architecture with Explanation}
\label{ch:architecture}

\section{System Overview}
\label{sec:arch-overview}

The proposed dental assisting system follows a pipeline-based, tooth-centric
architecture. A full OPG is first interpreted at the image level only to detect
teeth and assign tooth indices; all disease reasoning is then performed at the
tooth level. This separation is deliberate. Caries is primarily a crown-level
phenomenon and benefits from tight crops, whereas periodontal bone loss must be
assessed from a wider region that includes the root and adjacent alveolar bone.
Therefore, a single full-image classifier would not provide the spatial
specificity or the task-specific context required for clinically meaningful
outputs.

The target end-to-end system is organized into the following stages:
\begin{enumerate}
  \item OPG acquisition, quality check, and normalization.
  \item Tooth detection on the full panoramic radiograph.
  \item Tooth ordering and FDI number assignment.
  \item Tight-crop caries analysis for each tooth.
  \item Expanded-crop periodontal analysis for each tooth.
  \item Post-processing, confidence filtering, and report generation.
\end{enumerate}

The architecture diagram in Figure~\ref{fig:architecture} represents this
target pipeline. In the current project state, the disease-analysis branches
have been developed and evaluated independently, while the detection,
FDI-numbering, and single-script integration stages remain under active
development.

\section{Component Description}
\label{sec:arch-components}

\subsection{OPG Input}
The input to the complete system is a full panoramic radiograph. At this stage,
the image is treated as the common coordinate frame from which every later
tooth-level crop is derived. This is important because both the caries and
periodontal branches must stay spatially aligned to the same tooth index in the
final report. Any preprocessing performed here must therefore preserve tooth
geometry and avoid destructive distortion.

\subsection{Image Enhancement and Normalization}
This stage standardizes image intensity and size so that the later models
receive inputs with consistent dynamic range and dimensions. For the
periodontal CEJ estimation branch, local contrast enhancement through CLAHE was
explicitly tested because raw OPG crops showed large variations in local
contrast. For the classifier branches, the dominant standardization step is
resize to \(224 \times 224\) followed by ImageNet normalization, so that the
transfer-learned ResNet18 backbone operates on the expected input distribution.

\subsection{Tooth Detection and Segmentation}
The detection stage receives the normalized full OPG and produces one bounding
box per visible tooth. This is the point where the shared full-image coordinate
system is converted into tooth-level instances. The team architecture reserves a
YOLO-based detector for this task because it provides a pragmatic balance of
accuracy and inference speed for object localization on a large panoramic
image. However, this stage has not yet been fully integrated with the disease
modules in the checked-in codebase, and therefore it is described here as part
of the target system rather than as a completed deliverable.

\subsection{Multi-Disease Detection}
Once a tooth has been localized, two parallel crops are generated from the same
bounding box. The first is a tight crop intended for caries analysis. The
second is an expanded crop that includes root structure and surrounding bone
for periodontal analysis. This dual-crop strategy is one of the key design
choices in the project because it preserves a one-to-one mapping between tooth
identity and disease outputs while still allowing each pathology branch to use
the region of interest most relevant to its task.

\subsection{Severity Staging}
Detection alone is not sufficient for a clinically useful report. The system
therefore reserves a separate staging step after disease presence has been
predicted. In the current implementation, caries severity is handled by a
second DENTEX-based classifier that separates caries from deep caries, and
periodontal severity is handled primarily by overlap-based mild, moderate, and
severe classes derived from expert pathology masks. A CEJ-based percentage
measurement branch has also been explored for periodontal disease, but it is
currently treated as experimental because its OPG reliability is lower than the
overlap-based approach.

\subsection{Explainable AI}
The final intended system includes Grad-CAM-based visual explanations so that
each tooth-level prediction can be accompanied by a highlighted region of the
input crop. This component remains important for the next phase because
clinically acceptable decision support requires not only a categorical output
but also a visual rationale that can be inspected by a user. At the current
project stage, explainability is part of the planned integrated pipeline rather
than a fully finalized experimental result.

\subsection{Structured Clinical Report Generation}
The output stage combines every per-tooth decision into a structured report.
Each record is intended to include the FDI tooth number, caries status and
severity, periodontal status and severity, confidence, and associated visual
evidence. This is the stage that converts multiple specialized models into a
single clinically interpretable output. At present, the report schema has been
defined conceptually, but automated end-to-end report generation is still
pending.

\section{Design Rationale}
\label{sec:arch-rationale}

The tooth-centric formulation was chosen over a direct image-level classifier
because the final deliverable is a tooth-wise report, not a global disease flag
for the entire OPG. A modular pipeline is also a practical response to the
available datasets. DENTEX provides tooth-level caries labels, whereas the
Tufts data is much richer for periodontal analysis after region-to-tooth
mapping. Since no single public dataset in the current project contains all
required labels for detection, caries staging, and periodontal staging in one
consistent format, training one monolithic multi-task model would add
substantial supervision mismatch without providing a clear implementation
advantage at this phase.

ResNet18 was selected as the common classifier backbone for both branches
because it is lightweight, well understood, and stable under transfer learning
on limited dental datasets. Larger backbones were deliberately avoided in the
checked-in work because the available training sets are small enough that extra
capacity increases overfitting risk without a demonstrated benefit. The
trade-off is that the modular design shifts more responsibility to downstream
integration: numbering, report assembly, consistency checks, and confidence
filtering must still be implemented carefully so that independent models behave
as one coherent clinical support system.
