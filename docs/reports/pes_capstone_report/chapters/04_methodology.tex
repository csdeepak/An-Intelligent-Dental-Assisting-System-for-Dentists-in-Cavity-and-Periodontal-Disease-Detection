\section{Datasets and Task Allocation}
\label{sec:method-dataset}

This project relies on multiple public dental radiography datasets because no
single dataset in the current scope provides every label needed for tooth
detection, tooth numbering, caries staging, and periodontal bone-loss staging
in a mutually consistent format. Each dataset is therefore assigned a strict
role, and labels are not mixed across tasks unless a direct spatial mapping is
available.

\begin{table}[htbp]
  \centering
  \caption{Dataset roles in the current project.}
  \label{tab:dataset-role-summary}
  \begin{tabular}{@{}llll@{}}
    \toprule
    Dataset & Main annotation type & Role in this project & Current usage \\
    \midrule
    DENTEX & Tooth-level caries labels & Caries classification and staging & Used \\
    Tufts & Tooth boxes + pathology masks & Bone-loss analysis & Used \\
    CariesXrays & Lesion-level caries boxes & Lesion localization only & Reserved for future work \\
    \bottomrule
  \end{tabular}
\end{table}

The DENTEX dataset is used for the caries branch because it provides
tooth-centric caries labels that can be used directly for classification. In
the current checked notebook, the collaborator's pipeline treats DENTEX as two
sequential binary tasks: caries versus no-caries, followed by caries versus
deep caries. The Tufts dental dataset is used for the periodontal branch
because it provides the combination of tooth bounding boxes and pathology masks
needed to construct tooth-level bone-loss labels. CariesXrays is intentionally
not used for tooth detection or severity classification in this phase because
its annotation granularity is lesion level rather than tooth level; it is more
appropriate as a future auxiliary dataset for lesion localization.

For the Tufts branch, only images with all three required sources present
(bounding boxes, expert text, and pathology masks) were retained after joining.
This produced a working pool of 423 OPGs, from which 22,806 tooth-level crops
were constructed. The original crop distribution was strongly imbalanced:
approximately 96\% normal and 4\% diseased, corresponding to an imbalance ratio
of 23.84\(\times\). This imbalance heavily influenced the later resampling and
loss-design choices.

Figure~\ref{fig:tufts-coverage} explains why the full Tufts release could not

\section{Preprocessing}
\label{sec:method-preprocessing}

\subsection{Bounding Box Correction}
The most critical preprocessing correction on the Tufts data was the bounding
box format. The raw annotation uses corner points in the form
\([y_1, x_1, y_2, x_2]\), not the standard \([x, y, w, h]\) format assumed by
most image pipelines. Therefore, each box was converted using
\(x = x_1\), \(y = y_1\), \(w = x_2 - x_1\), and \(h = y_2 - y_1\). Without
this correction, all later crops would have been extracted from incorrect
locations and the entire periodontal training set would have been corrupted.

\subsection{Asymmetric Expanded Crop for Bone Loss Assessment}
For periodontal analysis, each tooth bounding box is expanded asymmetrically by
1.5\(\times\) in width and 2.0\(\times\) in height. The asymmetry is
anatomically motivated. Teeth in panoramic radiographs are substantially taller
than they are wide, so symmetric expansion would introduce unnecessary
horizontal contamination from adjacent teeth while still under-covering the
alveolar bone region. The expanded box is clipped to image boundaries before
crop extraction and resized to \(224 \times 224\).

\subsection{Overlap-Metric Based Labeling}
The standard Intersection over Union metric was rejected for bone-loss crop
labeling because the expert pathology masks are sparse relative to the expanded
tooth crop area. In practice, even genuine positive crops can produce IoU near
zero because the union term is dominated by the background area. The label used
in this project is instead based on overlap ratio:
\[
\mathrm{overlap} =
\frac{\text{non-zero mask pixels inside crop}}{\text{crop area}}.
\]
A threshold of 0.01 was used to separate normal and diseased crops after visual
inspection of the overlap distribution.

\subsection{Bounding Box Jitter for Detector Noise Simulation}
To reduce the train--test mismatch between perfect annotation boxes and
realistic detector outputs, a random perturbation of \(\pm 15\%\) is applied to
the Tufts tooth boxes during crop generation. This jitter simulates expected
localization noise from a future YOLO detector and makes the binary
periodontal classifier less sensitive to small crop misalignments.

\subsection{CLAHE Preprocessing for CEJ Estimation}
The CEJ estimation branch uses a different preprocessing path. Each crop is
enhanced with CLAHE (clip limit 2.0, tile grid \(8 \times 8\)) and then lightly
smoothed with a Gaussian filter. These steps are intended to improve the
visibility of the CEJ and bone crest landmarks in low-contrast panoramic crops.
They are specific to the heuristic CEJ branch and are not part of the main
classifier pipeline.

\subsection{Data Augmentation}
Two augmentation strategies were used in the project. First, the binary
periodontal training set used offline oversampling of the diseased class:
two augmented copies were generated for every diseased crop using random
horizontal flip, random rotation within \(10^\circ\), brightness jitter 0.2,
contrast jitter 0.1, and affine translation of 5\% in each axis. Second,
training-time augmentation was applied inside the binary classifier's data
loader. The collaborator's caries notebook defined a later augmentation block
for the severity stage, but the exported notebook shows that the final reported
run used the plain resize-and-normalize transform rather than the augmented
version. This is therefore treated as a limitation of the current caries
experiment rather than as an implemented benefit.

\subsection{Handling Class Imbalance}
The binary bone-loss task required explicit imbalance handling. The normal class
was undersampled from 17,473 training crops to 2,500, while all 237 original
diseased crops were retained and expanded to 711 through offline augmentation.
The resulting resampled training set contained 3,211 crops, while the
validation split was left untouched at 1,499 normal and 59 diseased crops.
This decision preserved realistic validation behavior while still making model
optimization feasible on the training side.

\section{Model Architecture}
\label{sec:method-model}

All currently completed classifier branches use ResNet18 pre-trained on
ImageNet, with the final fully connected layer replaced to match the target
task. The common choice of backbone keeps the implementation simple and makes
the crop design, preprocessing, and normalization strategy consistent across
modules.

\begin{table}[htbp]
  \centering
  \caption{Model configurations used in the current phase.}
  \label{tab:model-configs}
  \begin{tabular}{@{}llll@{}}
    \toprule
    Module & Input & Output layer & Role \\
    \midrule
    Caries Phase 1 & Tight tooth crop & 512 \(\rightarrow\) 2 & Caries / no-caries \\
    Caries Phase 2 & Tight tooth crop & 512 \(\rightarrow\) 2 & Caries / deep caries \\
    Bone-loss binary & Expanded tooth crop & 512 \(\rightarrow\) 2 & Bone loss / normal \\
    Bone-loss severity & Expanded tooth crop & 512 \(\rightarrow\) 3 & Mild / moderate / severe \\
    CEJ estimator & Expanded tooth crop & heuristic & Exploratory percentage estimate \\
    \bottomrule
  \end{tabular}
\end{table}

The tooth-detection branch is architecturally reserved for a YOLO-based model,
but it is not yet part of the integrated code path in this repository. For the
current report, YOLO is therefore described as a planned integration component
rather than a completed experimental result.

\section{Training Strategy}
\label{sec:method-training}

The caries and periodontal branches were trained separately because they depend
on different datasets and supervision formats. The collaborator's DENTEX caries
pipeline used transfer learning with ResNet18, \(224 \times 224\) resize, and
ImageNet normalization. Phase 1 used weighted cross-entropy with class weights
\([0.6377, 2.3156]\), Adam optimizer with learning rate \(10^{-3}\), batch size
32, and best-checkpoint selection by validation accuracy over 10 epochs. Phase
2 used a two-stage transfer protocol documented in the collaborator's notes:
warm-start from the earlier model, reset the classifier head, and then
fine-tune at a lower learning rate. The preserved final notebook output for the
best phase-2 run used weighted cross-entropy with weights \([0.6, 3.0]\) and
Adam with learning rate \(3 \times 10^{-5}\).

The binary bone-loss classifier used focal loss with \(\gamma = 2.0\) and
class weights \(\alpha = [0.642, 2.258]\), Adam optimizer with learning rate
\(10^{-4}\) and weight decay \(10^{-4}\), batch size 32, ReduceLROnPlateau
scheduling, and early stopping with patience 10. Training stopped after
32 epochs out of a maximum of 50, with the best checkpoint at epoch 22. The
three-class overlap-based severity classifier also used ResNet18 and focal
loss, but the best model occurred very early at epoch 2, which is a useful
indicator that the severity dataset remains small and comparatively easy to
overfit.

All model development recorded in the current repository was performed in
notebook environments on Google Colab or Kaggle with GPU support. The caries
notebook metadata indicates execution on Kaggle with an NVIDIA Tesla T4. The
periodontal notebooks were developed in Colab-based workflows with saved model
artifacts exported into the repository.

\section{Evaluation Metrics}
\label{sec:method-metrics}

For the classifier modules, the main evaluation metrics are precision, recall,
F1-score, and macro-F1. Accuracy is reported only as a secondary metric because
it is unreliable under strong class imbalance. The binary bone-loss task places
special emphasis on diseased-class recall because false negatives are
clinically more harmful than a moderate increase in false positives for a
screening system. For severity models, macro-F1 is treated as the most honest
selection criterion because it prevents the dominant class from masking poor
behavior on minority classes.

The periodontal data split was performed at the OPG level so that all crops
originating from the same radiograph remained in the same split, preventing
obvious leakage through jittered or augmented near-duplicates. In contrast, the
caries notebook operates on pre-generated train/validation folders from a
processed DENTEX dataset. The current checked artifact confirms that separate
train and validation directories were used, but patient-level provenance could
not be revalidated from the notebook export alone. This is therefore documented
as an experimental limitation rather than silently assumed away.

\begin{equation}
  \label{eq:f1}
  F_1 = \frac{2 \cdot \mathrm{Precision} \cdot \mathrm{Recall}}{\mathrm{Precision} + \mathrm{Recall}}
\end{equation}
