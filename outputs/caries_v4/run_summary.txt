--------------------------------------------------------------------------------
WHAT WAS TESTED
--------------------------------------------------------------------------------
Whether the caries gate's precision (0.398) and recall (0.740) are limited by the
amount of caries supervision it sees.

Measured first: DENTEX's disease subset carries 2,767 Caries + Deep Caries
annotations across 705 images. `crops_v3_phase1` uses 1,049 of them, because the
MD5 join that makes healthy teeth derivable only covers the 260 images with an
enumeration twin. 62% of the available caries supervision was unused.

v4 adds the 445 disease-only images as POSITIVES ONLY (plus their impacted /
periapical teeth as negatives). It deliberately adds NO healthy teeth: without an
enumeration twin there is no list of which teeth are present, and deriving
negatives by running the detector would inject detector false positives into the
negative class. The healthy negative class is therefore byte-identical to v3's.

  EVERY interval spans zero. Average precision -- the threshold-independent
  measure of the whole PR curve -- did not move. The precision gain and the
  recall loss are a shift ALONG the same curve, caused by the changed class
  balance moving what the 0.50 threshold means, not by better discrimination.

  CONCLUSION: 2.67x more caries training data did not improve the gate.
  The bottleneck is not the quantity of positive supervision.

--------------------------------------------------------------------------------
⚠ THE NUMBER IN phase1_gate_report.txt THAT MUST NOT BE QUOTED
--------------------------------------------------------------------------------
arm_b/phase1_gate_report.txt reports, on v4's OWN test split, caries
precision 0.71 / recall 0.80. Against v3's published 0.398 / 0.740 that reads as
a transformation. IT IS NOT ONE, and it must never be quoted that way:

                        n      prevalence   sens    spec    precision
  v4 on v3-test (863)   863      0.147      0.654   0.853     0.435
  v4 on v4-test (1218) 1218      0.324      0.800   0.843     0.710

Specificity -- the model-intrinsic quantity -- is essentially unchanged
(0.853 vs 0.843). Precision moved because v4's test split has 2.2x the caries
prevalence, since the disease-only images contribute positives and no healthy
teeth. Precision is a function of prevalence; comparing it across two test sets
with different prevalence measures the sets, not the models.

The only valid comparison is the like-for-like one above, on the shared
863-crop set, and it says the gate did not improve.

--------------------------------------------------------------------------------
WHY IT DID NOT WORK — stated as hypotheses, not conclusions
--------------------------------------------------------------------------------
1. The NEGATIVE class did not grow. A decision boundary between caries and
   healthy is set as much by the negatives as the positives, and v4 saw the same
   5,366 healthy teeth as v3. This follows directly from the positives-only
   design and is the most likely explanation.
2. Presumed-negative label noise, already recorded in crops meta.json: DENTEX
   annotates only diseased teeth, so a tooth with no annotation is PRESUMED
   healthy. Any lesion the annotators missed sits in the negative class as a
   false negative, capping achievable precision. Unmeasurable inside DENTEX.
3. The task may simply be near its headroom at this crop geometry. The tight
   1.0x crop cuts at the tooth boundary, and interproximal caries sits at the
   contact point between two teeth.
