VERIFICATION PERFORMED (21 Aug 2026)
--------------------------------------------------------------------------------
No torch is installed in any environment on this machine, so the checkpoints were NOT loaded.
They were verified structurally instead, by reading the .pth zip archives directly:

  - Each is a valid PyTorch zip archive with 128 entries and a readable data.pkl.
  - Pickle opcode scan confirms fc.weight / fc.bias present (the 512->2 head) and 122 tensor
    storage records in every file.
  - The two bundles carry the CORRECT and DISTINCT class_to_idx for their stages —
    {caries, no_caries} for Phase 1, {caries, deep_caries} for Phase 2. A swapped bundle
    would fail silently in the cascade, so this was the check worth making.
  - Tensor-payload digests (raw storage records, pickle wrapper excluded) confirm the
    lineage matches the notebook's execution order exactly:
        best_model      == final_model          IDENTICAL  (cell 52 load -> eval -> cell 60 save,
                                                            no training in between)
        best_phase2_final != best_phase2_fixed   different
        best_phase2_fixed != phase2_final_bundle different
        best_model        != best_phase2_final   different

STILL UNVERIFIED — requires torch, do this on the GPU box before trusting inference:
  - Actually loading each state_dict into a resnet18 and confirming it accepts them.
  - Re-running cell 119's evaluation to reproduce macro F1 0.77 from phase2_final_bundle.pth.

KNOWN LIMITATIONS OF THESE WEIGHTS
--------------------------------------------------------------------------------
  - Selected by ACCURACY, not macro-F1. The T0.3 fix rewrote the checkpointing cells (113,
    118) to select on macro-F1, which cleared their execution counts — these files predate
    that fix and came from the accuracy-selected code.
  - Evaluated on VALIDATION ONLY, on the pre-T0.2 split, with tuning and reporting on the
    same 133 crops. An independent image-level test split now exists and these weights have
    never been evaluated against it: data/dentex/splits_v2.json.
  - Phase 1 gate metrics DO NOT EXIST. Phase 1 of the notebook has zero saved outputs and
    zero execution counts across all its cells, so the gate's classification report was
    never recorded. The cascade's end-to-end error is unknown.
  - Trained WITHOUT augmentation (PAPER_MATERIAL.md §8.1) and with no LR scheduler and no
    early stopping.
