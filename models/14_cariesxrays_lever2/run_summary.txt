⚠️  THE SPLIT IS THIS PROJECT'S OWN, NOT FPCL's
--------------------------------------------------------------------------------
The official FPCL 4,800/1,200 split is NOT public — checked the FPCL GitHub repo
(0.5% sample, no ImageSets), the Google-Drive download (Annotations.zip +
JPEGImages.zip only), and the DVCTNet release. DVCTNet's paper used the split
"for fair comparison", so it exists but was shared privately by the authors.

This run uses a **seed-42 image-level 80/20 split (4,800 train / 1,200 val)** that
matches only their *ratio*. Every number below is "same dataset, same ratio, same
COCO-AP metric, DIFFERENT random test images" — **indicative of where an
off-the-shelf detector lands vs the published table, NOT head-to-head**. Do not
write it as "we beat / matched / lost to FPCL"; write it as "a generic 2024
detector reaches ~48 AP on this benchmark's data with no caries-specific method".

--------------------------------------------------------------------------------
CONFIG NOTES / DEVIATIONS
--------------------------------------------------------------------------------
- batch: requested 32, ultralytics auto-reduced to **16** after CUDA OOM at
  1024 px on the 40 GB card (the pre-registered fallback; args.yaml still shows 32).
- mosaic=0.0 by this project's house rule ("corrupts spatial context in medical
  imaging"). Mosaic usually helps small-object AP, so this is a conservative
  choice that may cost a few AP points — recorded, not an excuse.
- epochs 120 / patience 25 (canonical is 150/30) — cost cap, pre-registered.
- All other hyperparameters verbatim from the canonical detector config.
- 34 of 6,000 images carry no lesion box (24 train / 10 val) — kept as negatives.
- 27.3% of source XMLs carry a wrong <size> width; the builder reads dimensions
  from the decoded image, never the XML (RESULTS_LOG 2026-08-27a precedent).
