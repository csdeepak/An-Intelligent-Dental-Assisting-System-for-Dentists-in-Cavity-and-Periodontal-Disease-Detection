WHAT THIS REPLACES, AND WHY
--------------------------------------------------------------------------------
The gate in models/07_caries_cascade/ (final_model.pth) was trained on `phase1_legacy`,
whose rule is `category_id_3 in [1,3] -> caries, else -> no_caries`, applied to a file in
which EVERY annotation is a diseased tooth. Its `no_caries` class was therefore exactly
Impacted + Periapical Lesion and contained NO HEALTHY TEETH -- while the assembled
pipeline feeds it every tooth the detector finds, overwhelmingly healthy.

Measured in situ (RESULTS_LOG 2026-08-24f): it called 84.9% of 299 detected teeth carious
against 35 annotated. An 84.9% caries rate is not clinically plausible.

THE DATA FIX -- and why the previous attempt at it failed
--------------------------------------------------------------------------------
A `phase1_corrected` tree was built once by joining quadrant_enumeration to the disease
subset ON FILE_NAME. Invalid: the subsets number files independently, so train_0.png in
one is a different patient from train_0.png in the other. All 15,531 crops were discarded
(RESULTS_LOG 2026-08-21m). That entry concluded healthy teeth are "NOT derivable from
DENTEX".

That conclusion was too strong. The subsets share 260 BYTE-IDENTICAL images under
DIFFERENT filenames. Joining on MD5 of the image bytes recovers them exactly, and for
those 260 both annotation sets describe the same pixels in the same coordinate frame.

VERIFIED BY A FALSIFIABLE TEST, not by assertion: for a shared image, a disease annotation
and an enumeration annotation covering the same tooth must carry the same (quadrant,
position).
    agree 1255   disagree 22   ->  98.28% FDI agreement
    image dimensions match on 260/260
If these were different patients, agreement would sit near chance (~3% over 32 classes).
The builder re-runs this check every time and aborts below 90%.

WHAT THIS DOES NOT FIX -- report these with any result
--------------------------------------------------------------------------------
1. PRECISION IS 0.40. Six of every ten positives are still wrong. This gate went from
   unusable to plausible, NOT to reliable.
2. The annotated count is a FLOOR, not a complete label -- DENTEX annotates only diseased
   teeth. So 1.6x is an upper bound on how good the new gate looks, and the comparison
   cannot separate true false-positives from unannotated real caries.
3. PRESUMED-NEGATIVE ASSUMPTION. A tooth with no disease annotation is treated as healthy.
   That is absence of evidence: any lesion the annotators missed enters the negative class
   as a false negative, in training AND in the 0.40 precision above. Unmeasurable inside
   DENTEX.
4. TOOTH-TYPE CONFOUND. Caries concentrates in molars (44.3% at position 6 vs 1.5% at
   position 1), so some of what the model learns is tooth type, not pathology. Tested for
   a shortcut: aspect ratio ALONE scores 84.1%, exactly the majority baseline (-0.1% over
   it), so it is not trivially exploitable -- but per-position evaluation is the honest way
   to report this model.
5. 260 images is a small corpus, from one dataset, one scanner population.
